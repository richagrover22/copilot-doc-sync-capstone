# Phase 02: Architecture

## Approved Requirements and Technology

- Jira key: `CAPSTONEP-25`
- App folder: `task-manager-app`
- Runtime/framework: Python with Flask.
- Persistence: SQLite.
- Validation: pytest.
- Deployment scope: single-user local application; no accounts or external services.

## Application Structure

```text
task-manager-app/
  app.py                 # Flask app factory and routes
  task_store.py          # SQLite connection and task persistence
  templates/
    index.html           # Task list, filters, and create/edit form
  static/
    styles.css           # Responsive application styling
  tests/
    conftest.py          # Test app and temporary database fixtures
    test_tasks.py        # Route, CRUD, filtering, and validation tests
  requirements.txt       # Runtime and test dependencies
```

## Components and Responsibilities

1. **Flask routes** render the task list, accept create/update/delete form submissions, and apply optional status and priority filters.
2. **Task store** owns SQLite schema initialization and parameterized CRUD/filter queries. It is configured with an explicit database path so tests can use an isolated temporary database.
3. **Jinja template** renders tasks and provides forms for create/edit, status and priority selection, and filtering.
4. **pytest suite** exercises HTTP behavior and persisted results with Flask's test client and a temporary SQLite database.
5. **SDLC artifact generation** remains the responsibility of the Jira-driven orchestrator workflow. It writes phase artifacts and pipeline state under `docs/artifacts/${JIRA_KEY}/`; the app does not use Jira credentials or mutate orchestrator artifacts.

## Data Model

| Field | Type | Rules |
| --- | --- | --- |
| `id` | Integer | Primary key, generated by SQLite |
| `title` | Text | Required and non-empty |
| `description` | Text | Optional |
| `status` | Text | `todo`, `in_progress`, or `done`; defaults to `todo` |
| `priority` | Text | `low`, `medium`, or `high`; defaults to `medium` |
| `created_at` | UTC timestamp | Set on creation |
| `updated_at` | UTC timestamp | Set on creation and each update |

## Design Decisions

- Use server-rendered HTML forms rather than a separate frontend framework; this keeps the local single-user app small and aligns test coverage with pytest.
- Use SQLite for durable local persistence without requiring a database service.
- Keep the database in an application-owned `instance/` directory and allow tests to inject a temporary path.
- Use POST/Redirect/GET for mutations to avoid accidental repeat submissions on refresh.
- Validate task fields and allowed enum values on the server; parameterize all SQL.
- Keep the task application independent of live Jira access. The pipeline consumes the available Jira snapshot and generates its own artifacts.

## Verification Strategy

- Unit/integration coverage for task creation, retrieval, update, deletion, default values, invalid input, and status/priority filtering.
- Run the project's pytest suite and capture command/results in `phase-07-verification.md`.
- Manually inspect the rendered task list and forms for basic usability after implementation.
